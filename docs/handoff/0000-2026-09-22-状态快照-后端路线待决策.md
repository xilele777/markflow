## 1. 背景一句话

`F:/label/LabelHub/`（用户自研，Node/Express + React 19）与 `F:/label/submission/`（markflow，第三方，Java Spring Boot 后端 + React 18 前端）业务相同。评估结论：markflow的**领域设计**（五阶段多池流水线、状态机、AI 与人同构提交）明显更强，LabelHub 的**工程资产**（CI/CD、部署脚本、限流、指标、前端测试）更强。

## 3. 当前状态（待用户拍板）

**待决策：后端是否用 Node.js + TypeScript 重写，而不是沿用markflow Java 代码。**

用户不会 Java。助手建议：**重写为 TS，但"移植markflow的设计而不是代码"**——保留markflow前端（`markflow-web-前端`）与它依赖的 35 个接口契约、响应包络 `{success, code, message, data, timestamp}`、错误码字符串、枚举 code 值、状态机与多池派发规则；后端用用户熟悉的栈重写。

理由与代价见对话记录；要点：
- markflow Java 主代码 15,151 行含大量 DTO 双份与手写转换，TS 等价实现估计 6–9k 行。
- 中间件可简化：RocketMQ → BullMQ（Redis），去掉约 1 GB 内存占用；MySQL → PostgreSQL（用户 LabelHub 已用 pg，JSONB 天然适配 ext/config 列）；对象存储用 AWS SDK v3 同时兼容 MinIO 与火山 TOS（TOS 有 S3 兼容接口）。
- 代价：markflow 43 个集成测试全部作废需重写；行为细节以 Java 源码为唯一规格，翻译时需逐模块核对。
- 授权问题不变：前端与领域设计仍源自 onlyactwo，需书面授权；后端重写后不含其代码。

## 6. 关键事实速查（避免重新翻源码）

- markflow后端包：`com.onlyactwo.markflow`，控制器全部 `/api/*` POST（少数 GET 如 `/api/user/getCurrentUser`），登录 `POST /api/auth/login` 返回 `{token}`。
- 枚举 code：TaskStatus 1–5（PENDING_DISPATCH/LABELING/REVIEWING/DONE/REWORK）；TaskType 1–5（AI_LABEL/LABEL/AI_REVIEW/FIRST_CHECK/RECHECK）；TaskGroupType 1–6（PERSONAL + 五个池）；CaseStatus 1–4；WorkspaceRole 1–3（LABELER/REVIEWER/LABEL_ADMIN，接口返回英文名）；StageType 字符串 `aiPreLabel/label/aiPreReview/review/recheck`。
- 派发幂等键 `(caseId, taskType, dataSampleId)`；分发锁 `dispatch:case:{caseId}:pool:{poolType}`；自动回收定时任务；策略 FCFS=1 / FIXED_RATIO=2。
- sys_config 键：`jwt.secret`、`jwt.expireSeconds`、`tos.config`、`ai.configList`。
- 前端：`shared/api/http.ts` 只在 HTTP 401 时跳登录，其余非 2xx 用 `response.data.message` 弹 toast；`LoginPage` 固定跳 `/dataset`（应改用 `pickHomePath`）。
- 本机：Node 24、Docker 29、JDK 21、无 Maven。
