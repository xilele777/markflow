## 2. M2 落下的决定（后续沿用）

1. **对象存储**：`src/infra/object-storage.ts`，AWS SDK v3 S3；连接配置来自 `LINGSHU_S3_*` 环境变量（Java 存 `sys_config[tos.config]`，重写不再走库）。两个 S3Client：内网 endpoint 读写、`LINGSHU_S3_PUBLIC_ENDPOINT` 只用于预签名（SigV4 把 host 签进 URL，必须用浏览器最终访问的地址签）。**必须** `requestChecksumCalculation / responseChecksumValidation = 'WHEN_REQUIRED'`，否则新版 SDK 给预签名 PUT 加 `x-amz-checksum-*` 要求，浏览器直传 400。错误码沿用 `TOS_*`。`getObjectStream` 流式；`putObject` 目前只收 Buffer/string（M3 导出大文件改 `@aws-sdk/lib-storage` 的 Upload）。
2. **队列**：`src/infra/queue.ts`，BullMQ 6；`QUEUE_NAMES` 目前只有 `dataset-parse`，M3 的 `task-dispatched / task-completed / case-export` 按同样方式追加到 `QUEUE_NAMES`、`Queues`、`createQueues`、`startWorkers`。键前缀 `LINGSHU_QUEUE_PREFIX`（测试 `lingshu_test`，全局前置 obliterate）。默认 job 选项：attempts 3、指数退避 5s、成功即删、失败保留 1000 条；jobId `version-<id>` 去重。生产者在事务提交后 `add`，失败只记 error 日志（版本停留 PARSING）——outbox 留给 M3。消费者与 API 同进程（`src/app/workers.ts`），`main.ts` 关停顺序：停消费者（等在手任务）→ 关 HTTP → 释放连接。Worker 连接 `maxRetriesPerRequest: null`。
3. **解析**：`src/modules/dataset/dataset-parse.service.ts`。`iterateLines` 按 `\r\n|\r|\n` 流式拆行（StringDecoder 防多字节跨块），首行去 BOM；`ParseContext` 1000 行一批、错误明细 ≤ 100 条（超出只计数）、rowNumber 不含空行；schema 用 `compileJsonSchema(schema, {allErrors:true})`，消息格式 `$/path must be string` 取前 3 条；bizId 字符串/数字/布尔转字符串、容器与缺失为 null、超过 64 字符按单行错误跳过（Java 会整批失败）。成功 ext `{totalRowCount, successRowCount, skippedRowCount, sampleErrors, parseFailureReason:null}`；失败 ext 其它字段 null、原因 ≤ 500 字符（Java 同款）。**先 markFailed 再打日志**。业务失败在服务内消化，job 只在库/存储不可用时失败重试。
4. **迁移 0002**：`uk_dataset_space_name_active` 部分唯一索引（`WHERE deleted = 0`），逻辑删除后可重建同名。
5. 数据集 `spaceCode` 落库取 `workspace` 表的规范值（不是请求原文）；`DatasetSampleRepository` 只实现解析/预览所需方法。
6. `ServiceError.errorCode` 不可枚举；打日志把异常放 `err` 字段，序列化器带兜底。
