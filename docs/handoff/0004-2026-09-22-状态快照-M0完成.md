## 2. M0 落下的决定（后续里程碑沿用）

1. **成功包络 `code` 为 `'SUCCESS'`、`message` 为 `''`**（Java 原为 null；前端只看 `success`）。失败 HTTP 状态映射按规划 0002 §1，已实现于 `src/infra/errors.ts`。
2. **PostgreSQL 用 `citext` 复刻 MySQL 大小写不敏感**：username、space_code、各 `*_code`、dataset_name、case name、annotator、config_key 均为 citext，`=` 与唯一约束都不区分大小写。后续写查询不必再手工 `lower()`；模糊搜索仍需 `ILIKE`。
3. `label_task_group` 唯一键 `UNIQUE NULLS NOT DISTINCT (case_id, type, stage, annotator)`：每个 (case, type, stage) 只允许一个池组。所有 `ext`/json 列统一 `jsonb`，写入必须 `JSON.stringify`（pg 会把 JS 数组序列化成 PG 数组）。int8 已全局转 number。
4. **鉴权中间件只验 JWT，不查库**（与 Java 一致）；`getCurrentUser` 查禁用态。M5 做用户禁用时再决定是否在中间件加库查或令 token 失效。
5. `sys_config` 读取带进程内缓存（`SysConfigService`），`saveOrUpdate` 后失效；jwt.secret 不再每请求查库。
6. 限流：全局每 IP 600/min（`/api/health` 除外）、登录失败 `ip:username` 5 次/15 分钟，Redis 固定窗口，Redis 不可用时放行告警。都从 LabelHub 移植，未引入 express-rate-limit。
7. 环境变量命名 `LINGSHU_PG_*`（不是报告附录 B 的 `LINGSHU_MYSQL_*`），完整清单以 `lingshu-server/.env.example` 为准。MinIO 相关 `LINGSHU_MINIO_*` 目前只给 compose 用，后端 M2 再接 S3。
8. 迁移用 Kysely `Migrator` + 静态注册表（`src/db/migrator.ts`），启动时自动迁移；新迁移在 `migrations/` 加文件并登记。
