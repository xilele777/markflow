## 2. 对既有文档的订正（以本篇为准）

1. **markflow后端 JDK 是 17**，不是 21（pom `java.version`、`.java-version`、CLAUDE.md 一致）。对 TS 重写无影响。
2. **markflow Java 后端所有失败响应 HTTP 状态恒为 200**（`GlobalExceptionHandler` 无 `@ResponseStatus`/`ResponseEntity`，已亲自 grep 核实）。快照 0001 §5 与规划 0002 §1 写的「UNAUTHORIZED→401、FORBIDDEN/PERMISSION_DENIED→403、TOO_MANY_REQUESTS→429」不是原后端行为，而是 TS 重写的**有意改进**：前端 `http.ts` 只在 HTTP 401 时跳登录，对原后端 token 过期只会 toast 不跳转。决定：**保留规划 0002 的映射**（UNAUTHORIZED→401，PERMISSION_DENIED/FORBIDDEN→403，TOO_MANY_REQUESTS→429，其余 200），M0 实现。

## 3. 索引揭示的、需进入规划的新事实（不改规划 0002 正文，M3/M5 开工时据此写规则表）

- **驳回后二次质检不会自动产生**（后端索引 §7.5）：驳回不发 task_completed；重做完成后发的 task_completed 被入池去重吃掉。TS 重写必须修，方案在 M3 规则表里定（倾向：幂等键加 round，或驳回时把审核 task 重置为待审）。
- **流式模式（STREAM）没有推样本接口**，创建后不可用。M3 决定：不实现 STREAM，创建接口对 dataSourceType=2 返回 PARAM_INVALID，前端 Radio 保留但禁用（或 M5 再议）。
- **`label_task.biz_id` 永远为 null**，前端执行页显示的 bizId 来自 getSampleData。TS 重写创建 task 时填上。
- **AI 执行失败无重试、任务卡在在手状态**；规划 0002 M3 已含修复。
- **拦截器不检查用户禁用状态**（只在登录时检查）。M5 用户禁用功能要在鉴权中间件加检查（或使 token 失效）。
- **`/api/task/*` 不校验调用者是否为 annotator**；TS 重写至少校验 annotator 或系统管理员。
- 前端 `ExportResultSection` 早于 hooks `return null`（Hooks 规则违规）、`canViewAiConfig` 与后端权限不一致（后端允许 LABEL_ADMIN）：并入 M4 前端缺陷修复清单。
- LabelHub 的"截止提醒"实际只有到期结束/超时释放，没有提前预警；"用户禁用"未实现；M5 这两项是新写而非移植。
