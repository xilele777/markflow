## 2. M1 落下的决定（后续沿用）

1. **apiKey 加密**：AES-256-GCM，密钥 `MARKFLOW_CONFIG_ENC_KEY`（SHA-256 派生，≥ 32 字符，**新增必填环境变量**，`.env` 已补）。密文格式 `enc:v1:<base64url(iv‖tag‖ct)>`；无前缀的历史明文读取时原样返回、下次整表写入时自动加密。实现在 `src/infra/secret-box.ts`；M3 AI 执行器用 `AiConfigService.getAiConfigByCode` 取解密值。
2. **Redis 锁**：`src/infra/lock.ts`，键 `lock:<name>`，SET NX PX 轮询（默认 wait 3s / lease 10s）+ Lua 比对凭证释放；拿不到抛各模块 `OPERATION_CONFLICT`；Redis 异常上抛不放行。锁名沿用 Java（`user:username:`、`workspace:spaceCode:`、`workspace:member:user:`、`labelTool:create:`、`aiConfig:list`），用户名类键统一小写。数据库唯一约束作为第二道防线（`isUniqueViolation` 转业务码）。
3. **权限集中**：`src/modules/common/permission.ts`，按库实时查；组合规则 `checkCanManageWorkspace`（系统管理员 或 该空间 LABEL_ADMIN）、`checkCanViewGlobalAssets`（系统管理员 或 任意空间 LABEL_ADMIN）。M2 数据集、M3 case 直接复用。
4. **分页与搜索**：`src/modules/common/pagination.ts`（pageNum 默认 1、<1 报错；pageSize 默认 20、1-100）；keyword 用 `ILIKE` 并转义 `% _ \`（`likePattern`），按 create_time、id 降序。
5. **路由层 zod 只管类型**（`optionalString` / `optionalInt` 等允许 null 与缺省），空值与业务规则在服务层判断，返回 Java 同款错误码与文案；这样前端表单校验文案与原后端一致。
6. **贡献统计**：MySQL 方言改 PG（`->>`、`::varchar`、`to_timestamp … AT TIME ZONE … to_char`）；`SUM` 统一 `::bigint` 以走 int8 → number 解析器；按天时区 `MARKFLOW_TIMEZONE`（默认 Asia/Shanghai）；`avgCostMillis` 整除取整、无分母字段返回 `null`（前端 `?.`/`== null` 兜底，已验证空态与图表正常）。
7. **JSON Schema**：`src/infra/json-schema.ts` 用 ajv 8 严格模式（`strictSchema`、`validateFormats:false`），每次新建实例避免 `$id` 冲突；M2 解析样本复用 `compileJsonSchema`。
8. 测试辅助新增 `tests/helpers/seed.ts`（直接落库造 case / 组 / task / sample），M3 有正式接口后可替换。
