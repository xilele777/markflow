## 3. 命令、CI 和发布

根 package.json 提供 setup、dev:server、dev:web、infra:up/down、lint、typecheck、test、build、test:release、package:release。两份应用锁文件内容未变，仍独立安装依赖；没有 npm workspaces 或依赖提升。根锁文件只用于无依赖的命令入口。

GitHub Actions 统一到根 `.github/workflows/`：CI 包含 8 个 job，分别验证后端、前端、发布脚本和打包测试。旧应用工作流已移除。CD 保留 `MARKFLOW_DEPLOY_ENABLED == 'true'` 门禁，只检出一个确定提交构建两端，不再需要单独前端 repo / SHA / token 配置；当前未启用或远程运行。

打包默认路径依据脚本所属 monorepo 定位，不依赖调用目录；显式路径仍相对于调用目录。release.json 新增 repository / repositoryDirty，兼容保留的 server / web 字段均记录同一个 SHA；共享文档或 CI 的未提交改动也使整个包标记 dirty。拒绝混用其它仓库的前端。发布压缩包内部结构保持 server / web / scripts，Linux 激活和回滚协议不变。

新增 3 个打包回归测试覆盖默认目录、统一干净提交、凭据排除、共享未提交文件、重复 release、跨仓库混配和路径穿越。测试发现本机 Node 24 在中文临时路径原生 cpSync 目录复制会 EIO，采用带 filter 的 JS 遍历后通过；Linux 使用相同逻辑。
