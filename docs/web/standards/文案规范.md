# 文案规范

> **何时使用**：写任何界面文字（标题、提示、字段名、占位符、空态、按钮）前必读。

## 一、面向用户，不写技术术语
- 界面上**不出现开发视角的词**：`ossPath`、OSS、「直传 OSS」、「后缀决定解析格式」、IFRAME、`puck://…`、render、bizId（界面用「业务 ID」）等。
- 文件格式提示统一写「**支持 Jsonl 格式文件**」，不解释后缀机制。

## 二、列表 / 内容区
- **不加「页面大标题 + 描述性副标题」文字块**（如「数据集 / 管理标注…」）；页面位置由顶栏面包屑表达。
- **不显示「共 N 条」**这类汇总文字。
- **操作列用明确文字链接**（如「查看详情」「新版本」），**不用「…」图标**。
- **创建人直接显示姓名**，不加头像圆圈。

## 三、空间（workspace）
- 空间由**侧栏左下角的空间切换器**表达；**表单内不再让用户选择 / 重复展示「所属空间」**。

## 四、状态 / 类型文案
- 状态、类型、阶段的显示文案**以《状态映射.md》为准**，跨页保持一致（如 stage 一律用长名「AI 预标注 / AI 预审」）。

## 五、空态 / 错误态
- 空态：一句话说明 + 必要时给主操作入口（如「暂无任务组」）。
- 错误 / 失败：给可读原因，不暴露堆栈或内部键名。
